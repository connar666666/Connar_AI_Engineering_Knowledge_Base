# 邮箱服务器能力咨询邮件（最终重建版）

> 状态：历史重建版。根据已经确认的最终问题清单重建，可作为后续发送模板；不是旧工作区逐字原文。

您好，

我们目前正在设计集团内部 OA Agent 的 Email MCP 接入能力，希望通过 MCP 服务接入集团邮箱，为用户提供邮件查询、搜索、收发、回复、转发、历史追踪和邮件会话聚合等能力。

目前了解到，集团邮箱可以通过 IMAP / SMTP 配合第三方客户端授权方式访问。为了后续由项目组自行设计合适的接入方案，希望向您确认当前邮箱服务实际支持的接口、协议扩展、认证授权、会话能力和服务端限制。

我们主要希望确认以下客观能力。

## 一、邮箱访问接口与协议

1. 当前集团邮箱主要支持哪些访问方式？
2. 除 IMAP / SMTP 外，是否提供 Exchange EWS、类似 Microsoft Graph / Gmail API 的服务端接口，或集团内部开放 API？
3. IMAP 和 SMTP 的服务器地址、端口、TLS 模式及推荐认证方式分别是什么？
4. 是否提供企业通讯录、邮件群组或组织架构相关接口？

## 二、IMAP 能力与限制

1. 是否支持 `UID FETCH` 和按 UID 范围批量获取邮件？
2. 是否支持 `UIDPLUS`？
3. 是否支持 `IDLE`？如果支持，单个连接最长可保持多久？
4. 是否支持 `CONDSTORE` 和 `QRESYNC`？
5. 是否支持服务端 `SORT` 和 `THREAD`？
6. 是否可以通过 `CAPABILITY` 获取完整扩展列表？
7. 单用户、单 IP 或单应用允许的最大连接数是多少？
8. 是否存在查询频率、单次批量数量、附件大小或带宽限制？
9. 连接空闲超时、断线重连和异常封禁策略是什么？

## 三、邮件会话与标识

1. 邮箱服务是否提供原生 `thread_id`、`conversation_id` 或类似字段？
2. 是否存在一次性获取某个会话全部邮件的接口？
3. 如果没有原生会话标识，是否完整保留 `Message-ID`、`In-Reply-To` 和 `References`？
4. 邮件被移动、归档或转发后，上述标识是否保持不变？
5. 是否允许应用按多个 UID 批量或并发获取邮件，以便项目组自行构建会话关系？

## 四、第三方客户端授权与统一认证

目前我们已测试第三方客户端专用密码可以用于 IMAP / SMTP，希望进一步确认：

1. 专用密码的有效期、撤销和重建规则是什么？
2. 是否可以由管理员为企业用户统一开启第三方客户端访问？
3. 是否支持 OAuth2、应用凭据、服务账号、委托访问或其他不需要用户逐个配置专用密码的方式？
4. 是否可以基于企业微信或 OA SSO 身份映射到邮箱账号？
5. 是否提供账号状态查询能力，例如账号是否存在、是否启用 IMAP / SMTP、是否被锁定？
6. 用户离职、调岗或账号停用后，第三方授权如何自动失效？

## 五、发送与权限策略

1. SMTP 是否限制单封邮件的收件人数、附件大小或每日发送量？
2. 是否限制向外部域名发送邮件？
3. 是否存在群发、敏感群组、越级抄送或特定人员相关的服务端策略？
4. 是否支持查询邮件投递结果、退信原因或发送状态？
5. 是否提供反垃圾、敏感词、DLP 或附件安全扫描结果？
6. 是否支持应用级白名单、IP 白名单或调用来源限制？

## 六、运维、审计与数据合规

1. 是否提供访问日志、发送日志和异常登录日志？
2. 项目组是否能够通过接口或运维渠道查询失败原因？
3. 是否有邮件保留、归档、删除和恢复策略？
4. 是否允许 Email MCP 缓存邮件元数据、正文摘要或附件？对应的数据合规要求是什么？
5. 生产环境接入是否需要申请应用、备案 IP、证书或安全评审？
6. 是否提供测试账号、测试邮箱域或非生产环境？

如方便，也希望能够提供以下材料：

- 服务器地址和端口说明。
- 支持的协议与扩展列表。
- 认证和授权说明。
- 并发、频率和容量限制。
- 错误码或常见故障说明。
- 安全与审计要求。
- 测试环境和对接联系人。

以上问题主要用于确认邮箱服务器当前支持的客观能力和限制。具体采用 IMAP / SMTP、内部 API、线程自建、凭据托管或 SSO 映射，将由我们项目组根据返回结果自行设计。

感谢支持。
