# 手撕代码：算法与数据结构增量整理

## 1. Quickselect

Quickselect 用于在无序数组中寻找第 k 小或第 k 大元素，平均时间复杂度为 `O(n)`。

### 1.1 和快速排序的区别

快速排序会递归处理 pivot 两侧；Quickselect 只进入包含目标下标的一侧。

```text
partition
  ↓
pivot_index == target  → 返回
pivot_index < target   → 只搜索右侧
pivot_index > target   → 只搜索左侧
```

### 1.2 第 k 小与第 k 大

数组长度为 `n`：

```text
第 k 小的目标下标 = k - 1
第 k 大的目标下标 = n - k
```

这里是原数组排序后的下标，不是去重后的排名。题目如果要求“第 k 个不同元素”，需要先明确去重语义。

### 1.3 Partition 不变量

以左右指针分区时，要始终知道：

- 哪一段已经满足小于等于 pivot。
- 哪一段已经满足大于等于 pivot。
- 哪个位置暂时是“坑”。
- 循环结束后 pivot 最终放在哪里。

如果不清楚这些不变量，代码虽然看起来像快速选择，但容易出现覆盖、死循环或 pivot 丢失。

### 1.4 常见错误

- 把第 k 大写成 `k - 1`。
- 在递归时仍搜索两边，退化为快速排序。
- 重复元素下指针不移动。
- `left <= right` 和 `left < right` 混用。
- 返回的是元素下标，却当成元素值。
- 使用 `set` 后改变了题目对重复元素的定义。

## 2. 最长回文子串

### 2.1 中心扩展

最适合面试手写，时间复杂度 `O(n^2)`，空间复杂度 `O(1)`。

每个回文中心有两种：

```text
奇数长度：center = (i, i)
偶数长度：center = (i, i + 1)
```

从中心向两边扩展，直到字符不同或越界。

### 2.2 动态规划

状态：

```text
dp[i][j] = s[i:j+1] 是否为回文
```

转移：

```text
s[i] == s[j] 且 (j - i <= 2 或 dp[i+1][j-1])
```

时间 `O(n^2)`，空间 `O(n^2)`，适合解释状态设计，但通常不如中心扩展简洁。

### 2.3 Manacher

Manacher 可以做到 `O(n)`，但实现复杂，面试中只有在明确要求最优复杂度时再使用。

关键思想：

- 插入分隔符统一奇偶长度。
- 维护当前最右回文边界。
- 利用对称位置的回文半径减少重复比较。

## 3. 链表反转

### 3.1 完整反转

核心变量：

```text
prev：已经反转部分的头
curr：当前处理节点
next_node：提前保存未处理部分
```

执行顺序不能错：

```python
next_node = curr.next
curr.next = prev
prev = curr
curr = next_node
```

如果先修改 `curr.next` 再保存下一个节点，会丢失原链表剩余部分。

### 3.2 反转前 k 个节点

除了返回新头，还要保存：

- 第 k+1 个节点。
- 原头节点，反转后它会成为尾节点。

最后把新尾连接到剩余链表。

### 3.3 反转区间

常见方法是在区间前放一个 dummy 节点，再用头插法反转 `[left, right]`。

Dummy 的作用是统一处理 `left = 1` 的情况，避免单独修改头节点。

### 3.4 k 个一组反转

每组开始前先检查剩余节点是否达到 k 个：

```text
不足 k 个 → 保持原顺序
达到 k 个 → 反转并连接前后组
```

需要同时管理：

- 前一组尾节点。
- 当前组头和尾。
- 下一组起点。

## 4. LRU Cache + TTL

## 4.1 数据结构

```text
Hash Map：O(1) 找到节点
Doubly Linked List：O(1) 删除和移动节点
```

链表顺序：

```text
head <-> 最近使用 ... 最久未使用 <-> tail
```

虚拟头尾节点不保存业务数据，只用于减少边界判断。

### 4.2 Node 为什么有值

`Node` 需要保存：

```text
key
value
timestamp 或 expire_at
prev
next
```

`LRUCache.__init__` 不需要某个缓存值，它负责初始化整个容器：

```text
capacity
cache dict
TTL
head/tail sentinels
```

单个值属于 Node，不属于 Cache 构造函数。

### 4.3 Get 流程

```text
key 不存在 → -1
节点已过期 → 删除并返回 -1
节点有效 → 移动到头部并返回 value
```

是否在读取时刷新 TTL，需要提前定义：

- 固定 TTL：从写入开始计算，读取不续期。
- Sliding TTL：每次访问重新计算过期时间。

两种都合理，但代码和面试解释必须一致。

### 4.4 Put 流程

```text
key 已存在：更新值、时间，并移到头部
key 不存在：创建节点，加入字典和头部
超过容量：从尾部淘汰最久未使用节点
```

如果先创建新节点但没有删除旧节点，会造成字典和链表不一致。

### 4.5 TTL 与 LRU 的冲突

链表按最近使用排序，不一定按过期时间排序。因此不能只检查尾节点就认为所有过期节点都被清理。

可选策略：

1. 惰性删除：访问到节点时检查过期。
2. Put 前有限清理：从尾部尝试清理已过期节点。
3. 小顶堆：额外按过期时间管理，但要处理旧堆项。
4. 后台清理线程：工程系统可用，算法题通常不需要。

### 4.6 `show()` 的作用

`show()` 不是 LRU 的核心接口，而是调试函数，用来查看链表从最近使用到最久未使用的顺序。

它有助于验证：

- `get` 后节点是否移动。
- `put` 更新是否重复插入。
- 淘汰的是不是尾部节点。
- 过期删除后链表是否仍连接正确。

## 5. 命令行输入输出

算法测试可以不把数据写死在 `main()` 中，而是读取标准输入。

### 5.1 逐行读取

```python
import sys

for line in sys.stdin:
    line = line.strip()
    if not line:
        continue
    parts = line.split()
```

### 5.2 一次性读取

```python
lines = sys.stdin.readlines()
```

适合输入规模不大、需要先整体解析的情况。

### 5.3 LRU 命令示例

```text
put 1 10
put 2 20
get 1
show
sleep 3
get 2
```

解析后调用对应方法。对于未知命令、参数数量错误和整数转换失败，应给出明确错误。

## 6. 面试解释模板

回答算法题时建议按这个顺序：

```text
1. 先说明朴素方法和复杂度
2. 给出优化思路
3. 定义数据结构和循环不变量
4. 手写代码
5. 用边界样例走一遍
6. 说明时间和空间复杂度
```

边界样例包括：

- 空输入。
- 单个元素。
- 全部相同。
- k 在边界。
- 链表长度不足 k。
- TTL 恰好到期。
- 更新已存在 key。
