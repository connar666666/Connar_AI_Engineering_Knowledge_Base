# Email MCP：邮箱服务器能力确认清单

## 使用说明

这份清单用于向集团邮箱服务器或运维团队确认客观能力。技术方案如何选择由 OA Agent / Email MCP 项目组自行决定，因此问题应聚焦“服务器支持什么、限制是什么”，而不是要求对方替项目组设计方案。

## 一、访问接口与协议

1. 当前集团邮箱主要支持哪些访问方式？
2. 除 IMAP/SMTP 外，是否提供 Exchange EWS、类似 Microsoft Graph / Gmail API 的服务端接口，或集团内部开放 API？
3. IMAP 和 SMTP 的服务器地址、端口、TLS 模式和推荐认证方式分别是什么？
4. 是否支持通过服务端接口获取企业通讯录、群组或组织架构信息？

## 二、IMAP 能力

1. 是否支持 `UID FETCH` 和按 UID 范围批量获取邮件？
2. 是否支持 `UIDPLUS`？
3. 是否支持 `IDLE`，以及单连接可保持多久？
4. 是否支持 `CONDSTORE` 和 `QRESYNC`？
5. 是否支持服务端 `SORT` 和 `THREAD`？
6. 是否能通过 `CAPABILITY` 获取完整扩展列表？
7. 单用户、单 IP 或单应用允许的最大连接数是多少？
8. 是否有查询频率、批量拉取数量、附件大小或带宽限制？
9. 连接空闲超时、断线重连和异常封禁策略是什么？

## 三、邮件会话与标识

1. 邮箱服务是否提供原生 `thread_id`、`conversation_id` 或类似字段？
2. 是否有接口可以一次获取某个会话的全部邮件？
3. 如果没有原生会话标识，邮件是否完整保留 `Message-ID`、`In-Reply-To` 和 `References`？
4. 转发、归档、移动文件夹后，这些标识是否保持不变？
5. 是否允许应用按多个 UID 并发或批量获取邮件，以便自行构建会话？

## 四、第三方客户端授权与统一认证

1. 当前第三方客户端专用密码的有效期、撤销和重建规则是什么？
2. 是否可以由管理员为企业用户统一开启第三方客户端访问能力？
3. 是否支持 OAuth2、应用凭据、服务账号、委托访问或其他不需要用户逐个配置专用密码的方式？
4. 是否可以通过企业微信 / OA SSO 身份映射到邮箱账号？
5. 是否提供账号状态查询接口，例如账号是否存在、是否启用 IMAP/SMTP、是否被锁定？
6. 用户离职、调岗或账号停用后，第三方授权如何自动失效？

## 五、发送与权限策略

1. SMTP 是否限制单封邮件的收件人数、附件大小或每日发送量？
2. 是否限制向外部域名发送邮件？
3. 是否存在群发、敏感群组、越级抄送或特定人员的服务端策略？
4. 是否支持查询邮件投递结果、退信原因或发送状态？
5. 是否提供反垃圾、敏感词、DLP 或附件安全扫描结果？
6. 是否支持应用级白名单、IP 白名单或调用来源限制？

## 六、运维、审计与数据合规

1. 邮箱服务器是否提供访问日志、发送日志和异常登录日志？
2. 项目组是否能够通过接口或运维渠道查询失败原因？
3. 是否有数据保留、归档、删除和恢复策略？
4. 是否允许 Email MCP 缓存邮件元数据、正文摘要或附件？对应的数据合规要求是什么？
5. 生产环境接入是否需要申请应用、备案 IP、证书或安全评审？
6. 是否提供测试账号、测试邮箱域或非生产环境？

## 七、期望对方返回的材料

除逐项答复外，希望获得：

- 服务器地址和端口说明。
- 支持的协议与扩展列表。
- 认证和授权说明。
- 并发、频率和容量限制。
- 错误码或常见故障说明。
- 安全与审计要求。
- 测试环境和联系人。

## 最终原则

只需要邮箱服务器团队确认能力和限制。具体采用 IMAP/SMTP、内部 API、线程自建、凭据托管或 SSO 映射，由项目组根据返回结果自行设计。
