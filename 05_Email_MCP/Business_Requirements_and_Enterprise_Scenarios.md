# Email MCP：企业业务场景与需求边界

## 1. 为什么企业仍然需要 Email Agent

企业微信、OA 和即时通信适合快速协作，但邮件仍然承担大量非固定流程：

- 跨部门正式沟通。
- 对外客户、供应商和合作伙伴往来。
- 合同、报价、方案、会议纪要和附件传递。
- 需要抄送、留痕、长期检索和审计的沟通。
- 不适合被固定 OA 表单完全覆盖的临时流程。

因此 Email MCP 不只是“帮用户收发邮件”，而是把邮件变成 OA Agent 可查询、可操作、可追踪的业务数据源。

## 2. 核心用户场景

### 2.1 邮箱概览

用户说：

```text
总结我今天收到的邮件，按紧急、待回复、仅通知分类。
```

系统需要：

1. 获取指定时间范围内邮件。
2. 去重并识别会话。
3. 提取发件人、主题、时间、正文摘要和附件。
4. 判断是否需要行动。
5. 返回可追溯到原邮件的结果。

### 2.2 历史搜索

```text
查找过去三个月中与 A 供应商关于交付延期的所有邮件。
```

搜索条件可能包括：

- 发件人或收件人。
- 主题关键词。
- 正文关键词。
- 时间范围。
- 是否有附件。
- 已读、未读、星标等状态。

### 2.3 会话追踪

```text
把这个项目从第一次询价到最终确认的邮件往来按时间线整理出来。
```

这里不能只返回单封邮件，而要重建线程，区分：

- 原始邮件。
- 回复和再次回复。
- 转发。
- 主题被修改后的相关消息。
- 同一业务但不同线程的邮件。

### 2.4 写信、回复和转发

Agent 应该先生成草稿供用户确认，再执行发送。

推荐流程：

```text
用户描述意图
  ↓
Agent 检索相关上下文
  ↓
生成收件人、抄送、主题、正文、附件建议
  ↓
用户确认
  ↓
调用发送工具
  ↓
记录审计信息
```

高风险动作包括：

- 大范围群发。
- 外部域名收件人。
- 涉及敏感附件。
- 越级抄送。
- 自动代表用户作出承诺。

这些动作需要额外确认或策略限制。

### 2.5 附件理解

典型任务：

- 找到邮件中的报价单、合同或表格。
- 下载并总结附件。
- 判断是否缺少附件。
- 在回复时重新附上原附件或新增附件。

附件文件本体不适合长期塞入模型上下文，应保存到对象存储或临时文件系统，并在 Agent 上下文中只保留元数据和摘要。

### 2.6 待办和风险识别

Agent 可以从邮件中提取：

- 截止日期。
- 负责人。
- 承诺事项。
- 待回复问题。
- 延期、投诉、付款和合同风险。

但自动创建任务、发送回复或升级汇报之前，应遵循用户授权和企业策略。

## 3. 功能优先级

### P0：基础可用

- 列出邮件。
- 读取单封邮件。
- 条件搜索。
- 发送邮件。
- 回复邮件。
- 转发邮件。
- 下载附件。
- 标记已读/未读。

### P1：企业体验

- 会话聚合。
- 增量同步。
- 草稿管理。
- 邮箱文件夹管理。
- 抄送和密送。
- 审计日志。
- 用户与邮箱账号映射。
- 失败重试和幂等。

### P2：Agent 智能能力

- 邮件摘要与分类。
- 待办提取。
- 风险识别。
- 会话时间线。
- 跨线程业务聚合。
- 结合 OA、日历、联系人和知识库进行回复建议。

## 4. 非功能需求

### 安全

- 凭据加密保存。
- 最小权限。
- 用户隔离。
- 敏感字段脱敏。
- 发送前确认。
- 完整审计。

### 稳定性

- IMAP 连接池和超时。
- 断线重连。
- UID 增量游标。
- SMTP 发送幂等保护。
- 附件大小限制。
- 限流和退避。

### 可观测性

应记录：

- 用户身份。
- 调用了哪个工具。
- 访问了哪个邮箱和文件夹。
- 搜索条件和结果数量。
- 是否执行发送、回复或转发。
- 错误类型、耗时和重试次数。

## 5. 需求边界结论

Email MCP 不应该自行决定企业组织权限，也不应该默认允许 Agent 无确认发送邮件。

推荐责任划分：

```text
OA Agent：身份、授权、策略、确认、审计入口
Email MCP：协议适配、邮件模型、工具执行、错误标准化
邮箱服务器：账号、邮箱数据、服务器级访问控制和限流
```
