# ComfyUI_Bench：前端设计理解

## 1. 前端在项目中的角色

前端不是只负责展示页面，而是负责把复杂的 Project、Canvas、邀请、资产、生成任务组织成用户可理解的交互流程。

核心页面包括：

- 登录后首页。
- Project 列表。
- Project 详情。
- Canvas 页面。
- Asset Library。
- 邀请弹窗。
- 任务进度与输出结果。

## 2. Project 页面

Project 页面应该支持：

1. 查看项目列表。
2. 创建项目。
3. 进入项目。
4. 管理项目成员。
5. 邀请用户加入 Project。

Project 页面中的邀请不应该只是简单输入邮箱，而是应该支持搜索用户名或账号。

## 3. Canvas 页面

Canvas 页面是具体工作区。它应该支持：

1. 查看当前 Canvas 内容。
2. 管理 Canvas 版本。
3. 查看生成结果。
4. 使用素材库。
5. 邀请用户协作。
6. 提交生成任务。

Canvas 权限可以复用 Project 权限，但也可能有自己的权限。

## 4. 邀请弹窗设计

邀请弹窗建议流程：

```text
点击 Invite
  ↓
弹出 Modal
  ↓
输入用户名 / 邮箱关键词
  ↓
后端搜索用户
  ↓
选择用户
  ↓
选择角色
  ↓
发送邀请
```

弹窗中需要展示：

- 用户头像或名称。
- 用户名或邮箱。
- 角色选择。
- 是否已邀请。
- 是否已是成员。

## 5. 首页右上角信封图标

用户登录后的主页右上角需要一个信封图标，用于提示邀请信息。

建议逻辑：

```text
用户登录
  ↓
前端请求 GET /me/invites
  ↓
如果存在 pending invite
  ↓
信封图标显示红点或数字
  ↓
用户点击查看邀请列表
  ↓
接受或拒绝邀请
```

## 6. 前端状态管理

前端需要管理的状态包括：

- 当前用户。
- 当前 Project。
- 当前 Canvas。
- 用户权限。
- 邀请列表。
- 任务进度。
- 上传素材状态。
- 生成结果状态。

## 7. 前端设计重点

1. 权限决定按钮是否显示。
2. 邀请状态要清楚。
3. Project 与 Canvas 的层级关系要清晰。
4. 任务进度不能阻塞页面。
5. 生成结果需要能被追踪到对应 Canvas 和版本。
