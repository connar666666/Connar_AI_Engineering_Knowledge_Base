# 00_Conversation_Continuity

这个目录不是普通知识笔记，而是整个知识库的“对话状态恢复层”。

## 1. 为什么需要这一层

只保存最终技术结论，会丢失很多后续继续合作所必需的信息：

- 最初的问题是如何提出的。
- 哪些思路由用户先提出。
- 哪些方案由助手补充。
- 为什么放弃某些方案。
- 当前结论是已经实现，还是仍停留在设计阶段。
- 用户已经理解了什么，仍在哪些概念上容易混淆。
- 下一次讨论应该从哪里继续，而不是重新从基础概念开始。

这个目录的目标是让一个新的 GPT 工作空间在读取仓库后，能够尽可能恢复之前的合作上下文。

## 2. 推荐加载顺序

新工作空间开始时，按以下顺序读取：

```text
1. README.md
2. 00_Conversation_Continuity/NEW_WORKSPACE_BOOTSTRAP.md
3. 00_Conversation_Continuity/USER_COLLABORATION_PROFILE.md
4. 00_Conversation_Continuity/CROSS_PROJECT_DECISION_LOG.md
5. 00_Conversation_Continuity/OPEN_THREADS_AND_PENDING_VERIFICATION.md
6. 当前正在讨论项目的 README
7. 当前项目的 Conversation_History_and_Decision_Log.md
8. 当前问题相关的技术主题文档
```

不要一次把整个仓库全部塞入模型上下文。应先加载索引和当前项目，再按问题检索相关文件。

## 3. 来源标记

对话历史文档使用以下标记：

- **用户提出**：由 FangCong 主动提出的判断、问题、设想或设计方向。
- **助手建议**：由助手提出的解释、实现方式、风险或优化方案。
- **共同结论**：经过多轮讨论后双方已经对齐的方向。
- **已确认事实**：由代码、仓库、命令输出、文档或实际测试确认。
- **待代码验证**：必须继续读取真实实现才能确认。
- **待实验验证**：必须通过实验、指标或 Benchmark 证明。
- **已放弃 / 已修正**：早期理解或设计已经被后续讨论修正。

## 4. 文档类型

### Conversation History

保留讨论形成过程，不逐句抄录聊天，而是保存：

```text
问题背景
用户原始判断
助手补充
发生的认知修正
最终结论
仍未解决的问题
```

### Decision Log

保存关键架构决策：

```text
决策内容
提出来源
选择原因
替代方案
风险
当前状态
```

### Open Threads

保存尚未闭环的问题，使新工作空间不会把它们误认为已经完成。

### Bootstrap

提供一个可以直接粘贴到新 GPT 工作空间的启动说明。

## 5. 对公开仓库的隐私约束

当前仓库是公开仓库，因此不应写入：

- 登录密码、邮箱授权码、Token 和 Cookie。
- 私有服务器凭据。
- 未公开的员工个人数据。
- 企业内部敏感邮件正文。
- 用户真实面试官联系方式。
- 私有仓库中不适合公开的业务数据和源代码。

可以保存架构、流程、问题和抽象后的经验，但秘密信息应只保存在安全的凭据系统或私有文档中。

## 6. 对新助手的要求

读取这些文档后，新的助手应：

1. 不把设计设想说成已经实现。
2. 不重复解释用户已经明确掌握的基础内容，除非用户重新询问。
3. 先理解用户当前的具体困惑，再逐步展开，避免一次倾倒大量零散知识。
4. 对项目问题优先结合真实代码、文件路径和数据流。
5. 区分用户自己的原创设想与助手补充，不能把用户想法重新包装成助手结论。
6. 发现旧文档和最新代码冲突时，以最新代码为准，并更新知识库。
7. 对仍未验证的判断明确标记，不编造实验结果或实现状态。
