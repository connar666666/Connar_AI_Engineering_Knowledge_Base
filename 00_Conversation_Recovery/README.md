# 00_Conversation_Recovery

这个目录用于帮助新的 GPT 工作空间恢复长期对话状态。

它和仓库中的普通知识文档职责不同：

```text
普通知识文档
= 面向人类阅读的技术总结、架构设计和学习笔记

Conversation Recovery
= 面向新助手的项目状态、思路来源、合作方式和未完成问题
```

## 1. 目标

新的助手读取这一目录后，应该能够理解：

- 用户目前在做哪些项目。
- 每个项目为什么开始、当前进行到哪里。
- 哪些想法由用户提出，哪些由助手补充。
- 哪些已经成为共同结论。
- 哪些只是设计设想，仍需代码或实验验证。
- 用户已经理解哪些基础知识，不需要从零重复解释。
- 下一次对话应该从哪个问题继续。

## 2. 加载顺序

建议新的工作空间按以下顺序读取：

```text
1. NEW_WORKSPACE_BOOTSTRAP.md
2. USER_CONTEXT_AND_COLLABORATION_STYLE.md
3. PROJECT_STATE_INDEX.md
4. CORE_DECISIONS_AND_ORIGINS.md
5. OPEN_THREADS_AND_NEXT_ACTIONS.md
6. 当前项目目录下的技术文档
7. 需要时再读取其他专题文件
```

不要一开始把整个仓库全部放入上下文。先恢复索引，再按当前问题检索相关文档。

## 3. 信息来源标记

本目录统一使用以下标记：

- **用户提出**：由 FangCong 主动提出的判断、设想、问题或优化方向。
- **助手补充**：助手提供的解释、架构方案、风险分析或实现建议。
- **共同结论**：经过讨论后已经对齐的方向。
- **已确认事实**：由代码、仓库、命令输出、文件或实际测试确认。
- **待代码验证**：需要读取真实实现才能确认。
- **待实验验证**：需要实验、指标或 Benchmark 才能确认。
- **已修正理解**：早期理解后来被澄清或推翻。

## 4. 去重原则

这一层不重复保存完整技术内容，只保留：

1. 项目背景。
2. 用户原始思路。
3. 讨论中的关键转折。
4. 当前共同结论。
5. 未完成问题。
6. 应继续读取的技术文档路径。

例如，IMAP 的完整原理已经在 `05_Email_MCP/` 中保存；本目录只记录用户为什么关心线程能力、已经做过哪些判断和下一步要确认什么。

## 5. 更新规则

每次长期讨论形成新进展时，只在以下情况下更新这一层：

- 项目目标发生变化。
- 用户提出新的核心架构设想。
- 原有结论被推翻。
- 代码验证了此前的推测。
- 一个长期开放问题已经闭环。
- 出现新的高优先级下一步。

普通知识补充只更新项目文档，不必同步复制到这里。

## 6. 隐私边界

仓库当前为公开仓库，本目录不得保存：

- 密码、Token、Cookie、授权码。
- 企业内部邮件正文。
- 未公开的个人信息。
- 私有服务器配置。
- 不适合公开的源代码或业务数据。

可以保存抽象后的架构、问题、设计和经验。
